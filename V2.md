# FrankiFlow Mail v2

The `v2` branch implements a native Next.js App Router, React and TypeScript mail workspace. Keep its changes and Netlify deployment on `v2`. The classic attachment repair in PRs #13 and #14 was merged into `develop`; V2 is not merged into `develop` or `main`.

## Development

Use the existing `/workspace/frankiflow-mail` checkout with Node 24. No private build credentials or database container are required.

```sh
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
npm run dev
```

`/` requires Supabase sign-in and existing mailbox permissions. `/demo` is an isolated, fictional mailbox that never initializes or calls Supabase and never delivers mail. Demo messages, files, workspace tools and preferences persist only in this browser. Reset sample mailbox resets its messages, tools and sender names. Large attachments may exceed browser storage limits; the UI reports persistence failures.

Public backend configuration defaults to the existing project. `.env.local` can override the public values in `.env.example` for another backend. Never expose management, service-role, mail-provider or AI credentials through `NEXT_PUBLIC_*`. Real mail retains authentication and row-level security.

## Implemented workspace

- Responsive mail list and sandboxed conversation reader, desktop/mobile navigation, system/light/dark appearance, density, keyboard shortcuts, conversation grouping, preview preferences, default sender and read behaviour.
- Inbox, Sent, Starred, Drafts, Scheduled, Snoozed, All mail, Archive, Spam and Trash; search operators, labels, bulk actions, pinning, importance, restore, permanent deletion and ten-second move Undo.
- Plain/rich composing, formatting, lists, links, inline images, To/Cc/Bcc, contact suggestions, saved templates/signatures, reply/reply-all and forwarding with original attachment bytes. Reply-all excludes sender aliases and original Bcc recipients.
- Authenticated drafts save message content, reply/thread headers, attachment metadata and exact file bytes to the existing tables and private bucket. A replacement is completed before deleting the original draft. Failed saves keep the composer and original draft. Device recovery independently retains the in-progress compose in IndexedDB, scoped per user and separate from demo.
- Outbound files are archived before provider submission. Sent attachment discovery ignores stale flags. Missing historical outbound files can be recovered from the provider without resending. Inline images use CID references for delivery and original sanitized image HTML for the archive.
- Sending and scheduling retain the composer after failures. Confirmed delivery with failed bookkeeping shows a warning. Uncertain delivery blocks retries, preserves the warning through device recovery and requires an explicit delivery check before allowing another send.
- Native contacts, calendar, labels, filters, templates and server signature CRUD. Rules apply to newly loaded Inbox messages and on explicit request while the app is open; they are not a background server rules engine.
- Calendar events include timezone/DST conversion, attendees, online meeting links, recurrence, availability, reminders and downloadable ICS. Invitations and cancellations are prepared in the composer for review; event status changes after successful submission.
- Scheduled provider delivery and authenticated cancellation back to an editable draft. Snooze wakes messages while the app is open. Demo schedules never deliver mail.
- User-invoked AI writing suggestions through the existing authenticated service, sanitized preview and explicit insertion. Preferences and sender display names use the existing backend contracts.
- Foreground mail notices, optional sound and browser notifications, explicit device registration for background web push, installable icons/manifest and a generic offline screen. The service worker does not cache mailbox/API responses or expose mail offline.

The earlier device-only text signature setting remains available alongside synchronized saved signatures for continuity.

Regression fixes preserve reply threading across draft saves, reject empty attachments and truncated forward downloads, keep sample composers open when storage is full, restore malformed sample data safely, and persist deletion of the last sample message. Calendar displays use the event timezone; optional-only attendee lists are deliverable, and all-day events require an exclusive end date. Delayed downloads, sends and settings responses are checked against the active account. Failed preferences loads remain retryable and cannot overwrite stored settings. Text contrast and accessible file-control names were corrected in both themes.

## Validation

```sh
npm test
npm run build
npm run typecheck
npm start
# With the production server running in another terminal:
npm run test:e2e
npm run test:contract
npm run test:improvements
npm run test:workspace
npm run test:pwa
npm run test:edge-cases
npm run test:failures
npm run test:a11y
```

Browser suites default to `/usr/bin/chromium`. Set `CHROMIUM_PATH` to another Chromium executable and `BASE_URL` to the server under test. Screenshots go to ignored `test-results/`.

The contract suite intercepts Supabase requests to test authenticated UI/API behaviour, binary uploads/downloads, durable draft replacement, AI sanitization, inline image delivery, server resources and uncertain-delivery recovery. The failure suite additionally intercepts realtime WebSocket traffic and exercises delayed account loading, failed preferences, notification failures and authentication switches. The edge-case suite covers small screens, corrupt/quota-limited storage, blocked IndexedDB, optional-only invitations, event timezones and saved reply threads. Automated accessibility checks cover ten screens in light/dark themes against WCAG 2.1 AA rules. These synthetic responses and automated scans do not prove live provider delivery, permissions, device push delivery or complete manual accessibility compliance.

Backend code lives under `supabase/functions`. Check its Deno runtime independently of Next.js:

```sh
deno check --node-modules-dir=none supabase/functions/{send-mail,mail-v2-actions,mail-ai,mail-account-settings,mail-push}/index.ts
```

The GitHub `Mail v2 checks` workflow runs the production build, type checks, backend checks, unit tests and all eight browser suites on pushes to `v2`.

## Netlify branch deployment

`netlify.toml` builds Next.js and publishes `.next`; The pinned `@netlify/plugin-nextjs` adapter supplies the runtime explicitly, including when the site's original framework detection was static. Keep the production branch as `main`, with branch deploys enabled for `v2`. Push to `v2` to trigger that branch build. The user-confirmed branch URL is `https://v2--frankiflow-mail.netlify.app`, with an unauthenticated sample workspace at `/demo`.

A push or successful GitHub check does not prove Netlify deployment. Confirm the successful branch build and test its actual URL. The workflow can be dispatched on `v2` with `deployment_url` set to that HTTPS hostname (the earlier `v2--frankiholz.netlify.app` alias is also allowed by the test workflow) to run public branch tests after deployment. Real sign-in, provider delivery, signed downloads and web-push delivery require an authorized mailbox/device.

## Existing attachment repair

The deployed Supabase send function previously passed files to the provider but omitted storage uploads and attachment metadata. The repair archives files before delivery and supports authenticated recovery of historical provider files without sending another email. The reported PDF was restored to its original Sent message and a signed download matched its provider original: 580861 bytes, SHA-256 `980a0803b4ac12304dd55fd20206725bbe76b2160b5c55492bb191344080cb02`.

Preserve this behaviour, sender authorization and row-level security when updating backend functions. The V2 source also includes the backwards-compatible inline archive change, branch CORS origins and authenticated scheduled-cancellation endpoint. Deploy backend changes with JWT verification enabled and verify their active source separately from the frontend branch build.
